Enterprise Zoho CRM Engineering & Migration

Large-volume recruitment migration where JazzHR-sourced candidate resumes/files are processed from Google Drive, basic and professional candidate data are extracted and cleaned, duplicates are controlled, Zoho records are written and verified, and the original resume file is uploaded to the Zoho candidate record.

Production work reconstructionZoho CRM Engineer · Migration & Automation SpecialistGoogle Drive APIApploi source integrationZoho CRM / RecruitDelugeAI Resume ExtractionData Cleaning + Dedupe
Drive-first migration + parallel source control

JazzHR is not presented as an API source. Its migration lane starts in Google Drive, where the source resumes/files are stored. The pipeline derives candidate basics and professional data from those files, normalizes and deduplicates the candidate, validates confidence and facility mapping, writes the candidate to Zoho, and uploads the original resume file to that Zoho record. Apploi is handled as a separate source lane. The control center can run either lane alone or selected lanes in parallel with independent checkpoints and shared Zoho write throttling.

Context

Migration was a data-processing system, not a CSV import.

What needed to change

The JazzHR migration source was a Google Drive archive of candidate resume/source files rather than a live JazzHR API. That meant the migration had to derive usable candidate basics and professional information directly from the stored files, preserve the original resume, clean inconsistent values, prevent duplicate candidates and duplicate attachments, resolve facilities correctly, and still prove that every source file reached a final disposition.

What I designed

I designed a Drive-first JazzHR lane and a separate Apploi lane that normalize into one destination contract. For JazzHR, authorized Drive files are discovered and downloaded; basic identity/contact data and professional resume data are extracted; records are normalized, deduplicated, confidence-checked, and mapped to facilities; then Zoho is searched and written safely. After the candidate write is verified, the original resume file is uploaded as an attachment. The migration controller supports selecting one source or multiple sources and can process selected lanes in parallel with per-source checkpoints.

Architecture

Two source lanes, one controlled Zoho destination.

Parallelism is applied to source processing, while destination writes remain bounded by Zoho API limits and duplicate safeguards.

Data quality

Clean and deduplicate before the Zoho create.

Candidate quality is decided before the destination write.

Cleaning & normalization
  • Email trimming, lowercasing and validation.
  • Canonical phone comparison.
  • Name, whitespace, Unicode and null cleanup.
  • Address normalization where resume data is available.
  • Facility alias normalization before lookup.
  • Drive file ID + resume SHA-256 retained for traceability.
Deduplication controls
  • Already-processed source key / Drive file detection.
  • Normalized email + phone candidate matching.
  • Resume SHA-256 duplicate-file detection.
  • Name/contact similarity routed to manual review when not exact.
  • Zoho search before create prevents duplicate destination records.
  • Attachment duplicate guard prevents the same resume from being re-uploaded blindly.

Resume extraction

Basic and professional data from the Drive file.

The JazzHR lane derives the candidate record from the resume/source file.

After a Google Drive file is downloaded, the document is parsed for basic candidate information such as name, email, phone and address where present. The normalized resume text then feeds a structured AI extraction contract for professional data. Confidence and conflict checks happen before any field is allowed into the Zoho write.

Basic candidate data
  • First and last name
  • Email address

Professional data
