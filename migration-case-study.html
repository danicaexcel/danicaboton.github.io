Context

More than a CSV import.

What needed to change

Candidate records existed across multiple recruitment platforms while resume files were also maintained in Google Drive. A direct import would not solve inconsistent source values, duplicate candidates, duplicate resume files, facility-name variations, incomplete professional fields, or uncertain parsed values. At this scale, an uncontrolled load could create duplicate Zoho records, lose resume provenance, overwrite better source data, or make it impossible to prove that every source row was accounted for.

What I designed

I designed the migration as a staged data pipeline. JazzHR and Apploi records are read through source API integrations; Google Drive provides the resume files. Records are normalized, duplicate-controlled, enriched from resume content through structured AI extraction, validated against source precedence and confidence rules, mapped to facilities and Zoho fields, and written through controlled search/create/update operations. Every batch can be started, paused, resumed, stopped, verified, and reconciled.

Data quality

Clean and deduplicate before write.

Destination quality is decided before the Zoho create call.

Cleaning & normalization
  • Trim and lowercase email addresses.
  • Convert phones to a canonical comparison format.
  • Normalize names, whitespace, Unicode, dates, and null placeholders.
  • Normalize facility aliases and legacy naming before lookup resolution.
  • Preserve trusted source IDs and source-system provenance.
Deduplication decision ladder
  • Existing processed source candidate ID → update / skip duplicate create.
  • Normalized email + phone exact match → high-confidence candidate match.
  • Same resume SHA-256 → consolidate resume provenance.
  • Similarity match without exact key → manual duplicate review.
  • No match → candidate eligible for controlled create.

AI extraction

Professional data from resume evidence.

Resume files become structured professional fields.

After an authorized Google Drive resume is downloaded, the document text is extracted and normalized. A structured AI extraction contract converts the resume into professional fields that can be validated, confidence-scored, compared against trusted ATS fields, and mapped into Zoho.

Extracted professional data
  • Professional title / designation
  • Current and previous company
  • Professional skills
  • Years of experience
  • Education history
  • Employment history
  • Licenses / credentials
  • Professional summary
Validation boundary
  • Fixed structured schema rather than free-form model output.
  • Required-field and type validation.
  • Per-record confidence score.
  • Trusted ATS fields can take precedence over AI-derived values.
  • Source-vs-resume conflicts remain visible.
  • Low-confidence records route to review instead of auto-write.

Migration controls

Recoverable batch execution.

The migration can stop safely without losing its place.

StartLock the source manifest, create the run ID, initialize source cursors, and begin controlled processing.READY → RUNNING
PauseStop new source reads after the current safe record and persist the processing checkpoint.RUNNING → PAUSED
ResumeContinue from the next checkpointed source record without replaying the whole batch.PAUSED → RUNNING
StopClose the execution deliberately. A later restart becomes a new controlled run rather than an implicit continuation.RUNNING / PAUSED → STOPPED
Reliability & controls
  • Source pagination checkpoints
  • Source-ID idempotency
  • Duplicate-create guard
  • Resume file hash / provenance
  • Confidence and source-conflict gate
  • Facility lookup validation
  • Bounded retry and rate-limit backoff
  • OAuth / secret isolation
  • Destination read-back verification
  • Per-row final disposition
API write pattern

Before a create, the destination is searched using the approved match strategy. Writes use only mapped fields that pass the validation gate. After the write, the Zoho record is fetched again to verify the expected state. Retryable failures are replayed with bounded backoff; validation failures become review exceptions.

Outcome

Traceable from source to destination.

An operable migration pipeline, not a blind bulk import.

The resulting system preserves source-system IDs and Google Drive resume provenance, cleans inconsistent data, prevents uncontrolled duplicate creates, extracts professional resume information into structured fields, blocks uncertain values behind confidence and review rules, resolves facilities before writes, and verifies destination records after migration. Start / Pause / Resume / Stop controls and source checkpoints make long-running batches recoverable, while reconciliation ensures every source row ends with a migrated, duplicate-handled, or exception disposition.
