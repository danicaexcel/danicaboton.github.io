Monday.com Project Operations Control Center

A connected Monday.com implementation of the Project Operations model: projects, tasks, append-only work sessions, revision and rework tracking, timesheet approval, labor rates, audit history, portfolio reporting, and a defined n8n boundary for cross-board controls.

Operating problem

Project tracking was only one layer.

The goal was not to create another task board. The system needed to preserve project-to-task relationships while also modeling actual work sessions, revisions, approvals, labor costs, and audit history. The implementation was deliberately isolated with an [N] namespace so the pre-existing Monday workspace remained untouched.

Architecture

One connected operating model.

Monday.com remains the business interface and record layer. Native Monday functionality handles the operations it can enforce safely; n8n and the Monday API are reserved for cross-board validation, append-only session control, aggregation, and technical audit logic.

Boards

Complete schemas, not screenshot-only columns.

The public reconstruction exposes the full field model, including the columns that were outside the visible viewport in the original Monday screenshots.

[N] Master Projects

Project ID, client, owner, members, department, status, priority, start, deadline, timeline, planned hours, approved budget, actual/approved/rework hours, labor/rework cost, variance, progress, health, linked/open/overdue/completed task counts, last update, and notes.

[N] Master Tasks

Task ID, connected project, responsible person, collaborators, status, priority, dates, timeline, planned/recorded/approved/remaining hours, progress, revision count, rework hours/cost, approval requirement, type, activity, and notes.

[N] Work Sessions

Session ID, user, connected project/task, timestamps, duration, status, session type, revision reference, notes, and created date.

[N] Revisions & Rework

Revision ID, project/task links, request/assignment, reason, dates, status, additional planned effort, rework hours/cost, and resolution evidence.

[N] Timesheets & Approvals

Period, user, standard/revision/rework hours, submitted and approved hours, hourly rate, gross labor cost, approver, approval state, dates, linked sessions, and notes.

[N] Labor Rates + Activity Logs

Rate history is separated from work evidence, while activity logs preserve actor, action, source record, previous/new state, result, workflow, execution ID, and notes.

Control boundary

Native first. n8n where state crosses boards.

The architecture avoids using external automation for simple same-board actions. Advanced controls are only externalized when Monday's native automation model cannot enforce the requirement safely.

One active session per user

Before a task starts or resumes, n8n queries active work sessions. A conflicting session blocks the new start instead of allowing overlapping time evidence.

Append-only session history

Pause and Complete close the current session. Resume creates a new session rather than reopening or overwriting historical rows.

Approved labor cost

Work sessions aggregate into period timesheets. Only approved hours become final labor-cost inputs, while rework remains separately measurable.

Revision classification

Returned tasks create revision records and future related sessions can be classified as revision/rework until the revision is resolved.

Project rollups

Recorded effort, progress, cost, rework, and variance can be aggregated across the connected project/task/session hierarchy.

Auditability

Significant state changes produce structured log entries with record IDs, previous/new state, workflow, result, and execution IDs.
