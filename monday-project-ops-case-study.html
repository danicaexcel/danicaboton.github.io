Problem

Useful boards are not enough.

The operating interface and the evidence model need different responsibilities.

A project board can show Actual Hours, Approved Hours, Labor Cost, Rework Cost, Progress, and Health, but those values should not become editable sources of truth. A production system must be able to reconstruct every total from lower-level evidence: work sessions for actual time, revision records for rework context, approval records for payable hours, historical labor rates for cost, and immutable approved work lines for project allocation.

Design rule: Monday UI columns are convenient operating state. Event and approval boards are the evidence. Derived values are recalculated and written back for reporting, but they are not the authoritative source used to prove time or cost.
Data architecture

Eight connected boards with explicit data ownership.

The original seven-board model was revised before n8n implementation. The additional Approved Work Ledger separates timesheet approval from project/task cost allocation and prevents historical cost from changing when rates or operational totals change later.

Connected operating model

Projects and Tasks drive daily work. Work Sessions preserve time evidence. Revisions preserve rework context. Timesheets approve hours. Labor Rates provide effective-dated cost inputs. Approved Work Ledger lines freeze approved allocations. Activity Logs preserve system history.

Controls

Production rules enforced across boards.

The architecture prevents totals from drifting away from evidence.

One accountable task owner

Every task must connect to exactly one project and exactly one responsible person. The responsible person must be the project owner or one of its collaborators.

One active session per member

A worker cannot have two concurrent ACTIVE sessions. Pause closes the current session; Resume creates a new session. Historical timestamps are not reopened or overwritten.

Original work vs rework

Revision work is classified separately from original execution and linked to a revision record, so rework hours and cost remain measurable without rewriting the original task history.

Approval before cost

Recorded time is not automatically approved or payable. Timesheet approval creates locked Approved Work Ledger lines that become the source for approved project labor cost.

Effective-dated labor rates

A worker can have multiple historical rate records. Cost calculation resolves the rate valid for the relevant work/approval date instead of using only the worker’s current rate.

Derived fields are system-controlled

Actual Hours, Approved Hours, Labor Cost, Rework Cost, Cost Variance, Progress, and Health are calculated from authoritative records and written back for usability.

Idempotent cross-board writes

n8n actions use idempotency keys and correlation IDs so webhook retries or duplicate triggers cannot create duplicate work sessions, approvals, or ledger lines.

Reconciliation catches silent drift

A scheduled reconciliation compares active sessions, task/project links, derived totals, timesheets, ledger lines, and audit evidence, repairing safe differences and flagging unsafe ones.

Column revision

What changed before workflow build.

Schema changes made to support the objective functionality.

  • Master Projects: Approved Budget is treated specifically as Approved Labor Budget; Allocated Task Hours, Actual Original Hours, Rework Hours, Approved Hours, Approved Labor Cost, Approved Rework Cost, Remaining Labor Budget, Cost Variance, task counts, Progress %, Project Health, and Last Calculated At are derived.
  • Master Tasks: added Timer State, Current Session, Review Status, Completed At, Last Automation At, and Validation Status; Recorded Hours is separated into Actual Original Hours, Rework Hours, and Total Recorded Hours.
  • Work Sessions: made append-only and expanded with Session Type, State, duration, source/close reason, idempotency key, correlation ID, execution ID, and integrity status.
  • Revisions: added Root Cause Category, explicit workflow states, resolution evidence, linked work sessions, Approved Rework Hours, and derived cost.
  • Timesheets: converted into approval headers with recorded/approved original and rework hours, adjustments, approval lock, and linked ledger lines.
  • Labor Rates: converted to effective-dated historical records instead of one current rate per worker.
  • Approved Work Ledger: added as a new board to freeze approved hour/rate/cost allocation at worker × project × task × work-type level.
  • Activity Logs: expanded with actor type, entity references, state transition, result, correlation ID, idempotency key, retry count, and structured error detail.
n8n orchestration

Ten production workflow families.

The workflow layer is intentionally split by business responsibility rather than implemented as one giant automation. Every major workflow writes audit evidence and uses retry-safe cross-board updates.

01 · Work Session ControllerStart, Pause, Resume, Complete; one-active-session enforcement and append-only session creation.
02 · Project / Task ValidatorMandatory project link, single accountable person, membership validation, and invalid-state handling.
03 · Session AggregatorOriginal/rework duration aggregation and derived task/project actual-hour write-back.
04 · Revision ControllerRevision creation, root-cause classification, rework session linkage, review, and resolution.
05 · Timesheet GeneratorPeriod grouping of closed sessions into worker timesheet headers and approval-ready totals.
06 · Approval + Cost PostingApproval validation, historical rate resolution, locked ledger-line creation, and approved cost rollups.
07 · Escalation ControllerRequired escalation target/note validation, recipient notification, leadership visibility, and closure state.
08 · Project Health ProcessorProgress, overdue work, labor variance, open escalations, workload signals, and configurable health rules.
09 · Audit LoggerReusable event logging for actor/action/state/result/workflow/execution/correlation/retry/error evidence.
10 · Reconciliation & RepairNightly duplicate-session, orphan-link, aggregate, timesheet, ledger, and audit consistency checks.

Scope boundary

What stays native and what moves to n8n.

Native Monday.com

Boards, connected-board relationships, people columns, statuses, due dates, scheduled-work dates, priority, filtered personal views, Calendar, Timeline/Gantt, Updates, working attachments, SharePoint links, dashboards, and simple same-board notifications remain native.

n8n + Monday API

Cross-board validation, one-active-session enforcement, append-only session writes, idempotency, aggregation, revision classification, timesheet generation, historical rate resolution, approved-ledger posting, complex project-health calculations, structured audit logging, retries, and reconciliation run through n8n.
