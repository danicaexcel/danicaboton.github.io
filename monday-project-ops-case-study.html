What needed to change

The client needed more than a generic task board. Project ownership had to be explicit, tasks had to remain connected to projects, personal task and calendar views had to support filtering and scheduling without moving deadlines, escalations had to be visible, and leadership needed one place to see portfolio health, overdue work, and open escalations.

What I designed

I designed a connected Monday.com operating model with a portfolio-level project board, a mandatory project-linked task board, personal execution views, separate due-date and scheduled-work concepts, escalation fields with required notes, project-scoped communication, project-level SharePoint links, task-level working attachments, and leadership dashboards. The same model extends into work-session evidence, revisions, approvals, labor costs, and activity logs.

Portfolio evidence note: the client requirements documented here are the real requirement model supplied for the project. The interactive public environment is a reconstruction using synthetic people and operational values.
Requirements

The client’s
operating rules

Tasks cannot become a disconnected to-do list.

  • Project view — general: one Project Owner, multiple Collaborators, multiple Informed users, project status, due date, department, timeline, SharePoint folder, and project-scoped Updates/chat.
  • Task view — personal: tasks filter by person, project, status, priority, due date, and scheduled work.
  • Mandatory project link: every task belongs to a project. Ad-hoc work still belongs to a departmental project.
  • Responsible person: exactly one person is responsible for completing a task, and that person must be either the Project Owner or one of the project Collaborators.
  • Calendar: personal calendar separates authoritative due dates from optional scheduled work. Scheduling time does not move the deadline.
  • Priority: one priority value can override the normal schedule when attention must move immediately.
  • Escalation: a task can be escalated to another person only with a required escalation note, and open escalations must be visible to the recipient and leadership.
  • Communication: project-level conversation is restricted to people with project access and can reference tasks from the same project.
  • Files: permanent project files link to Microsoft SharePoint at project level; task attachments hold temporary working files, screenshots, and execution evidence.
  • Leadership: dashboards expose all projects with easy active/closed/future filtering, plus overdue projects/tasks and open escalations.

One connected Monday.com operating model.

Scope

What the
system delivers

What I built.

  • General project portfolio with owner, collaborators, informed users, department, status, deadlines, timeline, SharePoint link, progress, health, and financial visibility.
  • Personal task execution with mandatory project connection, one responsible person, filters, due dates, scheduled work, status, and priority.
  • Personal Calendar concepts that keep due dates separate from optional scheduled work.
  • Escalation target, required escalation note, escalation status, and leadership visibility.
  • Project-scoped communication model using Monday Updates/chat with task references from the same project.
  • Project-level permanent-file linking to SharePoint and task-level working attachments.
  • Append-only work-session history for Start, Pause, Resume, and Complete workflows.
  • Revision/rework tracking with separately measurable rework hours and cost.
  • Timesheet approval and controlled labor rates so only approved hours feed final labor-cost reporting.
  • Leadership dashboard views for active/closed/future projects, overdue work, escalations, planned vs actual effort, workload, rework, and cost variance.

Cross-board checks such as one-active-session enforcement, append-only session creation, complex rollups, timesheet generation, advanced audit logging, and retry-safe integrations are handled outside the front-end board state.
