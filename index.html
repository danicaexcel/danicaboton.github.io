Smart Recruitment Management System

A fully automated, end-to-end recruitment pipeline for AristaCare — spanning social sourcing, credential verification, AI-powered screening, CRM synchronization, and automated interview scheduling. Zero manual handoffs at any stage.

Problem Statement

Fragmented operations were blocking scale

AristaCare's recruitment operation was distributed across six or more disconnected platforms — job boards, ATS, social media channels, a CRM, a verification portal, and recruiter-managed comms. No system communicated with another. The result was inconsistent candidate tracking, frequent duplicate processing, limited applicant history visibility, and an unsustainable manual workload of 40+ hours per week.

Recruiters had no unified view. Leadership had no reliable data. Time-to-hire was slow. And there was no foundation for scaling candidate volume without adding headcount.

System Architecture

Event-driven pipeline from source to schedule

Social Lead (FB/IG/LinkedIn/Indeed) → Zapier Bridge (LinkedIn) → n8n Orchestration Engine → Verification Layer (Sapphire Check) → AI Screening (OpenAI) → Deduplication Check → Zoho CRM + Supabase → Interview Scheduling (Calendly) → Automated Outreach

Social Sourcing Layer

  • Facebook & Instagram lead forms via Meta API
  • LinkedIn lead gen forms bridged via Zapier webhook
  • Indeed job posting integration
  • Unified candidate intake regardless of source

Orchestration Engine

  • n8n handles all heavy workflow logic
  • Zapier bridges LinkedIn (no native n8n trigger)
  • Hybrid approach: reliability + flexibility
  • Error handling with retry logic on all API calls
Automation Logic

Step-by-step workflow orchestration

1
Lead capture & normalization

Candidate submits form on any source. n8n normalizes all fields into a standard schema: name, email, phone, resume link, source channel.

2
Deduplication check

Queries Zoho CRM for existing records by email and phone. If duplicate found, merges data and updates record without creating a second profile.

3
CRM sync & record creation

Creates or updates candidate record in Zoho CRM with all relevant fields. Custom modules track recruitment stage, source, and full interaction history.

4
Credential verification

Sapphire Check integration validates licenses, certifications, and background. Result logged to CRM and Supabase audit trail.

5
AI screening & scoring

Candidate profile sent to OpenAI. Evaluated against job description, required skills, and experience level. Returns score 0–100 with rationale.

6
Routing & scheduling

High-score candidates receive Calendly interview link via AI-generated personalized email. Low-score candidates receive automated rejection. All outcomes logged.

Error handling: Retry on API timeout (3 attempts, exponential backoff) On failure: Log to Supabase error table, alert recruiter via Slack Deduplication prevents double CRM entries on webhook replay LinkedIn Zapier bridge: fires once per lead, idempotent webhook endpoint

Problem Statement

Departmental silos were creating operational debt

The organization managed projects across a fragmented collection of individual boards, spreadsheets, and departmental workspaces. Each project had its own task board with no relational link to the portfolio. Leadership had no unified view of project health. Overdue tasks went undetected until manually reviewed. Risk escalations were informal and inconsistent.

The high automation credit consumption from monday.com's native automations created cost pressure. The goal: consolidate everything into a governed SSOT architecture with no per-credit automation overhead.

System Architecture

Monday as UI + database · n8n as orchestration engine

Master Projects Board → Board Relation → Master Tasks Board → n8n Engine (every 15 min) → Overdue Calculation → Days Remaining Update → Escalations Board (auto-created) → Leadership Dashboards

Monday Native (UI + DB)

  • Department mirror column — lookup from Projects
  • Status formatting and dashboard views
  • Manual data entry for project managers
  • Board relations: Projects ↔ Tasks ↔ Escalations
  • SharePoint links stored in file columns

n8n Workflow Engine

  • Overdue calculation: Yes / On time
  • Days remaining: computed daily delta
  • Auto-creates escalation for overdue tasks
  • Rate limited: 0.5s between API mutations
  • Schedule: every 15 min, weekdays 8AM–6PM ET

  • Severity: color_mm3j24e1 (auto = High)
  • Status: color_mm3jdh0j (auto = Pending)

Project Requests + Departments

  • Department reference data for dropdown consistency

Automation Logic

n8n overdue and escalation engine

Schedule: Every 15 min — Mon–Fri, 8AM–6PM ET (skips weekends) Monthly executions: ~860 (well within n8n free tier 2,500 limit) Workflow steps: 1. Query Master Tasks — filter: due date not empty, status not Completed/Cancelled/Archived 2. For each task: calculate Overdue (Yes if dueDate < today) 3. Calculate Days Remaining (dueDate - today, can be negative) 4. Update monday columns via GraphQL API mutation 5. If Overdue = Yes AND no open escalation for task: → Create Escalation record (Severity = High, Status = Pending, Date = Today) 6. If escalation already exists: skip (no duplicates) Rate limiting: 0.5s delay between mutations to respect monday.com API limits

Logistics Operations Automation System

A driver monitoring, late detection, and automated escalation system for a Singapore-based logistics subcontractor. Built on n8n + WhatsApp API + Google Sheets, the system reduced admin follow-up workload by 70% and eliminated missed pickups caused by undetected delays.

Problem Statement

Manual monitoring was creating operational burnout

A Singapore logistics subcontractor (3 drivers, 3 attendants, 2 vans) relied on the SPX mobile app for parcel scanning and assignment monitoring, but all tracking and follow-ups were entirely manual. Admins had to continuously watch the SPX screen and chase drivers by phone whenever a delay was suspected.

Drivers frequently started late without accountability. Missed pickups caused financial penalties and damaged client relationships. Store closing windows were being missed. The owner required constant updates that admins had to generate manually every hour. The admin team could not leave their screens during operations.

System Architecture

Automated monitoring and escalation pipeline

SPX App (manual entry) → Normalized Google Sheets → n8n Every 5 Min → Late Detection Logic → WhatsApp Driver Follow-up → Retry (×3) → Admin Group Escalation + Hourly Owner Report

Data Architecture

  • Raw SPX data normalized into automation-friendly sheet
  • One row per driver operation — no merged cells
  • Columns: Driver, Phone, Route, Planned Start, Actual Start, Status, Follow-up Count
  • Enables clean n8n querying without parsing overhead

Workflow 1: Late Detection

  • Runs every 5 minutes during operations
  • Compares Planned vs Actual Start Time
  • Sends WhatsApp follow-up to late drivers
  • Retries up to 3 times before escalation
  • Escalates unresponsive drivers to admin group
Automation Logic

Driver monitoring workflow

1
Read normalized operations sheet

Query Google Sheets every 5 minutes. Filter for drivers where Planned Start Time has passed and Actual Start Time is empty.

2
Late driver detection

Driver classified as LATE. Follow-up counter checked against sheet. If count is 0–2, proceed with WhatsApp message.

3
WhatsApp follow-up sent

"Reminder: Your pickup at [Store] was scheduled for [Time]. Please update your status." Follow-up count incremented in Sheets.

4
Retry logic (×3)

Waits 5 minutes per cycle. Up to 3 follow-up attempts before escalation trigger. Each attempt logged to sheet.

5
Admin escalation

If follow-up count reaches 3 with no response: driver marked Unresponsive, admin WhatsApp group notified, admins instructed to call manually.

6
Hourly owner report (Workflow 2)

Separate workflow runs hourly. Aggregates all driver statuses, flags delays and escalations, sends structured WhatsApp report to owner.

Escalation rule: followupCount >= 3 AND actualStartTime IS EMPTY Admin message: "⚠️ ESCALATION: Driver [Name] unresponsive after 3 follow-ups for [Route]." Owner report cadence: Every 1 hour during operations Sheet update: Each action logged — prevents duplicate follow-ups on restart

System Highlights

What makes this system defensible

  • Automation-first escalation: humans only intervene after 3 automated attempts fail — reducing unnecessary interruptions
  • Normalized data layer: raw SPX Excel sheets re-architected for automation compatibility without changing existing admin workflow
  • Idempotent follow-up logic: follow-up counter in Sheets prevents duplicate messages on n8n restart or retry

  • OCR roadmap: next phase uses Tesseract to auto-extract SPX screenshot data, removing the last remaining manual data entry step
