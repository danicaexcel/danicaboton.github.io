Smart Recruitment Management System

Problem Statement

Fragmented operations were blocking scale

Healthcare's recruitment operation was distributed across six or more disconnected platforms — job boards, ATS, social media channels, a CRM, a verification portal, and recruiter-managed comms. No system communicated with another. The result was inconsistent candidate tracking, frequent duplicate processing, limited applicant history visibility, and an unsustainable manual workload of 40+ hours per week.

Recruiters had no unified view. Leadership had no reliable data. Time-to-hire was slow. And there was no foundation for scaling candidate volume without adding headcount.

Fragmented recruitment systems

  • Job posting platforms
  • Applicant tracking systems
  • Social channels: Facebook, Instagram, LinkedIn
  • CRM and verification portals
  • Recruiter-managed communication channels

Lack of centralized intelligence

  • Previous applications and history
  • Interview outcomes and feedback
  • Rejection reasons and patterns
  • Communication history across channels
  • Full recruitment lifecycle data
System Architecture

Event-driven pipeline from source to schedule

End-to-end recruitment flow with Zapier + n8n orchestration

Social sourcing layer

  • Facebook and Instagram lead forms via Meta API
  • LinkedIn lead gen forms bridged via Zapier webhook
  • Indeed job posting integration
  • Unified candidate intake regardless of source

Orchestration engine

  • n8n handles all heavy workflow logic
  • Zapier bridges LinkedIn where n8n has no native trigger
  • Hybrid approach: reliability plus flexibility
  • Error handling with retry logic on all API calls
Automation Logic

Step-by-step workflow orchestration

1
Lead capture and normalization

Candidate submits on any source. n8n normalizes all fields into a standard schema: name, email, phone, resume link, source channel.

2
Deduplication check

Queries Zoho CRM for existing records by email and phone. If duplicate found, merges data and updates the record without creating a second profile.

3
CRM sync and record creation

Creates or updates candidate record in Zoho CRM. Custom modules track recruitment stage, source, and full interaction history.

4
Credential verification

Sapphire Check validates licenses, certifications, and background. Result logs to CRM and Supabase audit trail.

5
AI screening and scoring

Candidate profile is sent to OpenAI and evaluated against job description, required skills, and experience level. Returns score 0-100 with rationale.

6
Routing and scheduling

High-score candidates receive Calendly interview link via AI-personalized email. Low-score candidates receive automated rejection. All outcomes are logged.

Error handling: Retry on API timeout (3 attempts, exponential backoff) On failure: Log to Supabase error table, alert recruiter via Slack Deduplication prevents double CRM entries on webhook replay LinkedIn Zapier bridge: fires once per lead, idempotent webhook endpoint

Departmental silos were creating operational debt

The organization managed projects across a fragmented collection of individual boards, spreadsheets, and departmental workspaces. Each project had its own task board with no relational link to the portfolio. Leadership had no unified view of project health. Overdue tasks went undetected until manually reviewed. Risk escalations were informal and inconsistent.

The high automation credit consumption from monday.com's native automations created cost pressure. The goal: consolidate everything into a governed SSOT architecture with no per-credit automation overhead.

Key challenges

  • Duplicated task data across locations
  • No single source of truth for portfolio health
  • Manual overdue tracking and escalation
  • Inconsistent reporting for leadership

Automation Logic

n8n overdue and escalation engine

Schedule: Every 15 min — Mon-Fri, 8AM-6PM ET (skips weekends) Monthly executions: ~860 (well within n8n free tier 2,500 limit) Workflow steps: 1. Query Master Tasks — filter: due date not empty, status not Completed/Cancelled/Archived 2. For each task: calculate Overdue (Yes if dueDate < today) 3. Calculate Days Remaining (dueDate - today, can be negative) 4. Update monday columns via GraphQL API mutation 5. If Overdue = Yes AND no open escalation for task: → Create Escalation record (Severity = High, Status = Pending, Date = Today) 6. If escalation already exists: skip (no duplicates) Rate limiting: 0.5s delay between mutations to respect monday.com API limits

Logistics Operations Automation System

A driver monitoring, late detection, and automated escalation system for a Singapore-based logistics subcontractor. Built on n8n + WhatsApp API + Google Sheets, the system reduced admin follow-up workload by 70% and eliminated missed pickups caused by undetected delays.

Problem Statement

Manual monitoring was creating operational burnout

A Singapore logistics subcontractor (3 drivers, 3 attendants, 2 vans) relied on the SPX mobile app for parcel scanning and assignment monitoring, but all tracking and follow-ups were entirely manual. Admins had to continuously watch the SPX screen and chase drivers by phone whenever a delay was suspected.

Drivers frequently started late without accountability. Missed pickups caused financial penalties and damaged client relationships. Store closing windows were being missed. The owner required constant updates that admins had to generate manually every hour.

Operational challenges

  • Admins manually monitored SPX app continuously
  • Drivers started late without accountability
  • Admins constantly chased drivers by phone
  • Missed pickups from undetected delays
  • Owner micro-managed operations constantly

Business impact

  • High admin stress and burnout
  • Financial penalties from missed pickups
  • Delayed warehouse handovers
  • Poor management visibility
  • Inability to scale without adding headcount
Data Architecture

Normalized operational data layer

The original Excel sheets were not automation-friendly — containing merged cells, summary rows, and inconsistent formatting. A normalized operational data layer was created to enable automation.

Raw Operations Sheet → Normalization Layer → Automation-Ready Sheet → n8n Workflows → WhatsApp Columns: Date | Driver Name | Phone | Route / Area | Planned Start Time | Actual Start Time | Actual End Time | Status | Followup Count | Remarks
System Architecture

Automated monitoring and escalation pipeline

Logistics automation workflow with n8n + WhatsApp

Workflow 1: Driver Late Detection

  • Runs every 5 minutes
  • Compares Planned vs Actual Start Time
  • Sends WhatsApp follow-up to late drivers
  • Retries up to 3 times
  • Escalates to admin group if unresponsive

Workflow 2: Hourly Owner Report

  • Runs every hour
  • Aggregates driver statuses
  • Flags delays and escalations
  • Sends structured WhatsApp report
  • Reduces owner micro-management
Automation Workflow 1

Driver late detection and automated follow-up

01Read normalized operational sheet from Google Sheets every 5 minutes.
02For each driver with Planned Start Time passed and Actual Start Time empty: classify as LATE.
03Send WhatsApp reminder to driver and increment follow-up counter in sheet.
04Wait 5 minutes and retry up to 3 attempts.
05If no response after 3 retries: mark Unresponsive, notify admin WhatsApp group, instruct admins to call manually.
Driver message: "Operations Update: Your scheduled pickup at [Store] at [Time] requires attention. Please confirm your status or call dispatch." Admin escalation: "ESCALATION: Driver [Name] unresponsive after 3 follow-ups for [Route]. Please contact immediately."
